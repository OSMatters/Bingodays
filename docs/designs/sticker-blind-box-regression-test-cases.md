# BlindBox 整体回归测试用例

版本：2026-09-07；依据当前 BlindBox 工作区代码、最新弹窗交互及产品约定。

共 107 条用例：P0 60 条、P1 43 条、P2 4 条；另有 8 条跨功能组合路径。参数化用例包含多组输入，实际执行次数多于 107 次。

本文件是待执行的回归测试方案，不是测试通过报告。本次只整理用例，没有执行购买、云端故障注入或全量回归，没有修改业务代码。所有用例初始状态为「未执行」；已有单元测试仅代表部分底层规则有覆盖，不能替代真机端到端验收。

## 1. 测试基准与判定口径

| 项目 | 本轮基准 |
|---|---|
| 发券日 | 每日 04:00 至次日 03:59:59；00:00 不重置。当前代码使用调用方 Calendar，生产调用默认设备 Calendar；时区风险见第 8 节 |
| 每日赠券 | 非会员 1 张，会员 3 张；静默结算，进入首页或盲盒页不自动弹窗 |
| 会员升级 | 当日已按非会员额度结算后升级，目标额度从 1 提升至 3，补差 2；首次结算前已是会员则直接 3 |
| 券上限 | 所有来源合计最多 20；赠券被上限截断的部分不补领，消费后当日不能再次领取这部分 |
| 未登录的历史日期 | 当前实现不累计缺席日期，只结算当前发券日；已到账旧券保留 |
| 积分兑换 | 默认 100 积分换 1 张，每发券日最多 1 次；会员与非会员相同。远程支持价格变更，但次数必须为 1 |
| 领取结果 | 点击券余额后，优先展示未查看的实际到账数量；已查看后进入兑换弹窗。升级结果最多补差，不承诺无条件再送 3 |
| 兑换提示 | 未兑换显示「每日限兑 1 次」；已兑换显示「今日已兑换」并禁用按钮；成功和已兑换提示次日再来、每日 04:00 刷新 |
| 券不足 | 点击开盒时先结算当日赠券，再判断余额；仍不足显示兑换入口及实际差额。兑换、领取后均不自动提交第二次开盒 |
| 候选盒 | 非会员 4 个，会员 6 个；同一主题允许出现在多个盒位，所有用户均可玩所有开放主题 |
| 开盒 | 每批 9 个位置；单抽/随机消耗 1 券；端盒消耗该批当前未开位置数 N，不能照设计图固定扣 10 |
| 批次与概率 | 生成时固定结果及概率模式；每批最多 1 隐藏。普通模式单位置隐藏 1%，全常规已集齐且隐藏未获得时，新批次为 5%；对应整批含隐藏概率为 9% / 45% |
| 常规款与混盒 | 不承诺一盒集齐所有常规。Pets 有 11 常规，Cozy Daily 有 8 常规。当前生成器按洗牌循环填充，不能把“混盒”误判为所有位置独立重复抽样 |
| 自动揭晓与补货 | 候选首次可见后开始 45–180 分钟自动揭晓调度；每次维护最多揭晓一个，全候选区保留至少一个可开位置。自动揭晓不扣券、不送贴纸。售罄后 24 小时补货 |
| 收集完成 | 当前主题全常规及隐藏均集齐后退出候选；My Box 已获收藏保留；所有活跃主题完成有完成状态 |
| 兑换提交机制 | CloudKit 预留资格和容量 → 积分流水落库 → CloudKit 发券；失败通过同一请求恢复。不是积分与券同库一次原子写入 |

每次操作均核对四项：积分流水、券余额、盒位状态、贴纸库存。错误提示或成功动画不能单独作为通过依据。

## 2. 准备与执行方式

### 测试环境

- UI 预览：`-DebugBlindBoxPreview`，只用于样式及本地交互；不能据此判定真实积分、订阅和 CloudKit 已通过。
- 联调：`-DebugBlindBoxLive`，独立测试 iCloud 账号、沙盒订阅和可控远程目录；真实账号不得用于故障注入。
- 离线预览：`-DebugBlindBoxOffline`；真实离线另测 Wi-Fi/蜂窝断开、弱网、网络正常但 CloudKit 不可用。
- 双设备：同一 iCloud 测试账号 A/B；另备不同账号 C，用于数据隔离检查。
- 至少覆盖最小支持系统和 iOS 26、窄屏手机/常规手机/大屏；如果当前版本支持 iPad，同时验收 iPad。具体机型、构建号、目录版本、会员来源写入执行记录。
- 时间测试优先通过现有可注入 `now/calendar` 和测试数据库推进；实际跨日 UI 另做真机验证。不要只改手机时间后把客户端结果当成防作弊验收。

### 测试数据约定

P=可用积分；T=券余额；E=本发券日已兑换次数；Q=本发券日已结算赠券权益额度（0/1/3）；R=未查看赠券结果；N=当前批次未开位置数。

除专门测试赠券的用例外，初始化为「当日赠券已结算且回执已查看」，避免打开页面自动结算导致初始余额变化。数据通过测试夹具准备，禁止在生产钱包直接改余额。

边界值：P=0/99/100/101/199/200/10000；T=0/1/17/18/19/20；E=0/1；N=0/1/2/8/9。身份为非会员、会员、升级中、过期、恢复购买、权益暂未同步。

### 优先级与记录

- P0：重复扣费、丢失积分/券/收藏、越权开盒、重复领奖、跨账号污染、交易恢复错误；必须全部通过。
- P1：核心交互、刷新时序、会员引导、目录与迁移；发布前通过或有明确的阻断/处置结论。
- P2：视觉、长文案、极限尺寸、辅助功能等表现；严重遮挡主操作时升级为 P1。
- 每条记录：用例 ID、构建/目录版本、设备/系统、账号/身份、初始 P/T/E/Q、步骤、实际结果、结束余额/流水、通过/失败/阻塞/未执行、缺陷链接、截图或日志时间。
- 参数用例必须逐个参数执行；任一参数失败，该用例不能整体标记通过。

## 4. 必跑组合路径

单条通过后，再用同一账号连贯执行，检查页面间状态残留：

1. 新非会员 → 静默 +1 → 点击查看 → 关闭重开为兑换 → 花 100 分换 +1 → 单抽 → My Box → 次日领取+兑换。核对赠券与兑换来源分别记账。
2. 非会员已领取且已兑换 → 开通会员 → 仅补 +2 → 当日兑换仍禁用 → 次日赠 3、仍只兑 1。
3. 会员 T=19 → 赠券截断 +1 → 消费 3 → 当日不补赠 → 合法兑换 +1 → 次日再结算。
4. 非会员 T=0/N=8 → 券不足 → 升级或兑换 → 返回详情 → 再次端盒仍不足时差额更新；不得自动开盒或显示旧差额。
5. 兑换在扣分后杀进程 → 换设备恢复 → 原设备同步 → 检查唯一流水 → 次日再兑换。
6. 单抽提交成功后动画前杀进程 → 恢复揭晓 → My Box 对账 → 该盒端盒 → 补货 24h → 新批次。
7. 最后一款常规收集成功 → 检查旧批不改 → 生成新批为隐藏追逐 → 获隐藏 → 主题从候选消失、My Box 保留。
8. 已兑换弹窗停留跨 04:00 → 资格刷新 → 点击兑换 → 网络超时 → 重开弹窗 → 不重复扣分。

## 5. 结果对账与故障通过条件

- 券余额 = 初始券 + 实际日赠 + 实际补差 + 已完成积分兑换券 − 已成功用户开盒耗券。系统揭晓为 0，查看弹窗为 0。按真实提交顺序核算截断，不用日终余额倒推赠券。
- 本次兑换积分消耗 = 已提交的唯一兑换请求各自价格快照之和；普通回归默认每笔 100。其他积分来源/支出必须单独列账。
- 每款收藏增量 = 成功用户开出的该款数量；不能包含系统开位；总开盒成功结果数与总扣券量相同。
- 每请求 ID 最多一个有效结果/有效积分流水；任意在途故障恢复后不保留“积分永久已扣但券无记录”或“有券但永不扣分”。
- 并发用例在数据同步稳定后核对 A/B 云端及本地，不要求所有瞬时 UI 同步；不得在仍有 pending 请求时提前标通过。
- 失败用例应附失败阶段、请求 ID、提交时间和恢复后账目；“没看到成功弹窗”不能等同于“交易没有成功”。

## 8. 当前代码审阅发现的待验证风险

以下是测试风险，不是本次已执行确认的故障；不通过本文件擅自修改规则。

1. **设备时间与时区（B11/B12）**：GrantDay 注释表示未来才会持久化时区；目前使用 Calendar.current。赠券有负日期差保护，但积分兑换按日期标识是否相同判断次数，必须分别测试回拨/前调。不能声称已有服务端统一日界线或完整防改时钟能力。
2. **旧账号会员补差（C12）**：缺少 settledDailyTicketAllowance 时按当前身份额度作为已结算基线。兼容解码通过不代表老用户当天升级一定补到 2 张。
3. **跨账本一致性（E04–E10/D12）**：积分流水和盲盒账户分步提交；旧 PRD 中“一次同库原子事务”描述与现实现不一致。尤其验证跨设备流水未同步、跨日恢复及另一积分消费竞争。
4. **回执与真实展示（E14）**：回执先确认消费，再显示 UI；这之间中断可能有到账但无提示。普通预览验证不能证明展示可靠。
5. **旧日文案（B07）**：「明天再来」适用于发券日语境；00:00–03:59 实际下次重置是当天 04:00。执行时标注文案是否误导，不能把日历“明天”当系统多锁一天。
6. **目录与未上线门禁（H07/H10）**：Live/Preview 都为 debug-only。发布构建入口、目录部署及真实云端同步需要独立验收。
7. **混盒与独立随机（F14）**：现生成器是洗牌循环，不是每位独立抽样。测试应验证当前算法和“不保证全常规”的说明，不把设计图里的样例或“混盒”一词扩展成未定义概率模型。
8. **坏数据和离线浏览（H06/H09）**：未确认所有异常数据可自动修复、所有入口都能在失败状态保留缓存浏览；这两项须以实际执行结果为准。
